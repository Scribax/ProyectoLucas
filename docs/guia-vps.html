🔌 Conectarse al VPS

Desde tu PC, abrí una terminal y conectate por SSH (reemplazá la IP por la de tu servidor):

$ ssh root@TU_IP_DEL_SERVIDOR

Te pide la contraseña (o usa tu clave SSH) y entrás al servidor.

📁 Dónde está la app

El proyecto vive en /opt/granja-avicola. Casi todos los comandos se corren parado ahí:

$ cd /opt/granja-avicola

🚀 Actualizar la app (deploy)

Cuando hay cambios nuevos en el código, la forma recomendada es usar el script update.sh. Hace todo solo: backup, baja los cambios, reconstruye y levanta.

$ cd /opt/granja-avicola $ bash scripts/update.sh

update.sh hace: backup automático → git pull → rebuild con --no-cache → levanta todo → health check.

Primer despliegue (servidor nuevo)

Solo la primera vez, en un VPS recién armado:

$ chmod +x scripts/*.sh $ bash scripts/setup.sh
ℹ️
No hace falta tocar la base de datos a mano. Al arrancar, el backend aplica las migraciones, borra triggers viejos y recalcula los saldos automáticamente.

🩺 Ver estado y logs

Para saber si todo está corriendo bien:

# ¿Responde el sistema? $ curl http://localhost/health
# Ver qué contenedores están corriendo $ docker compose ps
# Ver logs en vivo (Ctrl+C para salir) $ docker compose logs -f
# Logs solo del backend, últimas 50 líneas $ docker compose logs backend --tail 50

🧹 Liberar espacio en disco (prune)

Cada vez que reconstruís la app, Docker deja imágenes y contenedores viejos que ocupan espacio. Con el tiempo el disco se llena. Estos comandos limpian esa basura sin tocar lo que está en uso.

1. Ver cuánto espacio ocupa Docker

$ docker system df

Te muestra cuánto pesan imágenes, contenedores y volúmenes, y cuánto es "reclaimable" (recuperable).

2. Limpieza segura (recomendada)

# Borra contenedores parados, redes sin usar e imágenes colgadas $ docker system prune -f

El -f evita que te pida confirmación. Es seguro: no toca lo que está corriendo.

3. Limpieza más profunda (libera más)

# Además borra TODAS las imágenes que no estén en uso por un contenedor activo $ docker system prune -a -f
⚠️
Con -a se borran todas las imágenes no usadas. No hay drama: la próxima vez que levantes la app, Docker las vuelve a construir/descargar (tarda un poco más esa vez).

4. Limpiezas puntuales

# Solo imágenes colgadas (dangling) $ docker image prune -f # Solo contenedores parados $ docker container prune -f # Caché de builds viejos (suele liberar bastante) $ docker builder prune -f
🚨
NUNCA uses docker system prune --volumes ni docker volume prune a la ligera en este servidor: ahí vive la base de datos. Si borrás el volumen de Postgres, perdés todos los datos. Hacé un backup antes si tenés dudas.

Rutina sugerida para liberar espacio

$ docker system df # 1. ver cuánto hay para limpiar $ docker system prune -a -f # 2. limpiar imágenes/contenedores viejos $ docker builder prune -f # 3. limpiar caché de builds $ df -h # 4. confirmar espacio libre en disco

💾 Backups

El script backup.sh guarda un respaldo comprimido de la base de datos y de las facturas, y borra los backups de más de 30 días.

# Backup manual $ bash scripts/backup.sh # Restaurar un backup $ bash scripts/restore.sh backups/granja_2024-01-15_14-30-00.sql.gz

Programar backup diario (cron)

$ sudo crontab -e # Agregá esta línea (backup todos los días a las 3 AM): 0 3 * * * cd /opt/granja-avicola && bash scripts/backup.sh

🧮 Diagnóstico de saldos

Para verificar que todos los saldos de clientes estén cuadrados (debería dar descuadrados: 0):

# Reemplazá TU_TOKEN por un token de admin $ curl -H "Authorization: Bearer TU_TOKEN" \ http://localhost/api/clientes/diagnostico/saldos

El token lo obtenés logueándote como admin en la app. Al arrancar, el backend ya recalcula todos los saldos solo.

⚠️ Cosas a tener en cuenta

SituaciónQué hacer
Antes de cualquier cambio grandeHacé un backup: bash scripts/backup.sh
El disco se está llenandoCorré la rutina de prune (sección 6)
"Demasiadas peticiones"Ya está corregido; reconstruí el backend si persiste
El navegador apunta a localhost:3001Reconstruí el frontend (update.sh ya lo hace)
El sistema pide reiniciarsesudo reboot cuando no haya nadie usando la app
💡
Regla de oro: ante la duda, primero backup, después tocás. Y nunca borres volúmenes de Docker sin estar 100% seguro.
